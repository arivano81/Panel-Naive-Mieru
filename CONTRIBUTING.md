# Участие в разработке

## Перед началом

1. Проверьте `ROADMAP.md` и существующие issue, чтобы не дублировать работу.
2. Для исправления ошибки опишите воспроизведение, ожидаемое и фактическое поведение.
3. Не добавляйте секреты, адреса рабочих серверов, клиентские конфиги или необезличенные логи.
4. Изменение VPN-бинарника, firewall, маршрутизации или systemd должно иметь отдельный план
   проверки и отката.

## Требования к изменению

- сохраняйте совместимость действующих установок и выключайте новые протоколы по умолчанию;
- проверяйте конфиг до перезапуска службы и не перезапускайте незатронутые VPN-компоненты;
- используйте закреплённые версии и SHA-256 для загружаемых бинарников;
- добавляйте минимальный regression-тест для исправленной ошибки или нового поведения;
- запускайте `npm test --prefix panel`; Bash-код также должен пройти `bash -n` и ShellCheck в CI;
- не объединяйте несвязанные изменения в один commit.

## Документация

Если изменение влияет на установку, настройку, доступ, безопасность или поведение панели,
обновите `README.md` простым языком. Описание должно отвечать на четыре вопроса:

1. Что изменилось для пользователя?
2. Что нужно сделать?
3. Где проверить результат?
4. Как безопасно отменить изменение или восстановить доступ?

Команды должны быть готовыми к копированию, а предупреждения — находиться до опасного действия.
Русский README является основным; `README.en.md` обновляется в том же изменении. Значимое
пользовательское изменение также добавляется в `CHANGELOG.md` и при необходимости в `ROADMAP.md`.

## Проверка перед публикацией

```bash
npm test --prefix panel
git diff --check
```

GitHub CI дополнительно проверяет Debian 12/13, синтаксис Bash, ShellCheck, закреплённые бинарники,
SBOM и изолированные canary. Изменение считается готовым только после зелёного CI.

Сообщения об уязвимостях отправляйте по правилам [SECURITY.md](SECURITY.md), а не через issue.
