# Зашифрованный backup — спецификация

## Пользовательский сценарий

Администратор открывает **Settings → Backup & Restore**, повторно вводит текущий пароль панели,
задаёт отдельную парольную фразу длиной не менее 12 символов и получает файл
`*.rixxx.enc.json`. При восстановлении фраза вводится до выбора файла. Панель её не сохраняет
и не может восстановить. Старый `rixxx-panel-backup` JSON принимается только на импорт.

## Формат и криптография

Контейнер имеет отдельный tag `rixxx-panel-backup-encrypted`, schema `1` и содержит только
параметры KDF/cipher и ciphertext. Ключ длиной 256 бит выводится через `scrypt` с новым
16-байтовым salt (`N=32768`, `r=8`, `p=1`). Данные шифруются AES-256-GCM с новым 12-байтовым
IV; format/schema входят в AAD. Salt, IV, tag и ciphertext кодируются canonical Base64.

Параметры KDF не принимаются из файла произвольно: импорт разрешает только закреплённый набор,
поэтому файл не может незаметно ослабить KDF или навязать чрезмерный расход памяти. Размер
plaintext ограничен 16 MiB, чтобы Base64-envelope оставался внутри лимита API 25 MiB.

## Модель угроз

- Кража файла не раскрывает пароли пользователей и администратора без парольной фразы.
- Изменение ciphertext, tag, IV либо AAD обнаруживается GCM до JSON-разбора и любых записей.
- Экспорт требует активной admin-сессии, CSRF-token и повторного пароля администратора.
- Экспорт, inspect и import используют отдельный rate limit; ответы помечены `no-store`.
- Парольные поля имеют `type=password`, очищаются после операции и не журналируются.

Защита не спасает от слабой/утраченной парольной фразы или уже скомпрометированного браузера
администратора. Парольную фразу следует хранить отдельно в менеджере паролей.

## Миграция и откат

Новых plaintext-экспортов нет. Старый JSON импортируется прежним путём, после чего следует сразу
создать зашифрованную копию. Внутренний backup schema не меняется: расшифрованный объект проходит
существующие validate, DB transaction, config apply, health check и automatic rollback.

## Проверки

`tests/backup-crypto.test.js` проверяет round-trip, отсутствие plaintext-секретов, неверную фразу,
подмену ciphertext и downgrade KDF. `tests/feat-backup.test.js` проверяет закрытый API-контракт,
а `tests/backup-restore.test.js` — прежнюю транзакцию восстановления и возврат рабочего состояния.
